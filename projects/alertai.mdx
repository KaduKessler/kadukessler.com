contentEn: |
  ## Outcome and my contribution

  I joined Education with the system already in production. My contributions include PDF and Excel reports generated in the background, asynchronous face enrollment with device synchronization, and deployment pipelines. I work on the .NET backend and React frontend alongside the team.

  ## Context

  AlertAI is an AI security platform with multiple products on a shared core — Sports and Education today, with others in development. I work on that platform and specifically on Education (facial-recognition access control and real-time monitoring).

  I joined the Education codebase already in production, built by other developers before me.

  ## What I built

  - Backend features in .NET over PostgreSQL and frontend features in React across the Education product, including access-control hardware integration (turnstiles)
  - A reporting module, end to end: the report service architecture, PDF (QuestPDF) and Excel (ClosedXML) exporters, and reports such as student attendance, events and audits, with a reports screen in the app
  - Background job infrastructure (Hangfire) now used across the platform: reports generated in the background with granular progress and ETA, cooperative cancellation, stuck-job detection and deduplication, documented in the repository's engineering docs
  - Migrated a synchronous integration workflow to async processing, working through the concurrency issues that surfaced
  - Asynchronous face enrollment with per-device synchronization and progress, adapters for three device brands, and a flow to change a person's enrollment type
  - Device management: active health checks, manual reconnection and an improved controller list
  - Background services that survive database outages or slowness, and event routes that return an error instead of silently dropping events
  - SMTP email notifications and push notifications, plus school-system integrations
  - CI/CD for the API and the frontend: a test job, VPS deploy with staging, backup, config merge and rollback, and a two-stage deploy with a manual gate on migrations

  ## Focus

  Working through concurrency and reliability issues that only show up under real device and network conditions.
